# Роли и права доступа

Статус: **проект, не реализовано.** Сейчас в схеме есть роли `owner`, `admin`, `staff` (`prisma/schema.prisma`, enum `Role`), но серверный код их не проверяет: любой вошедший пользователь может всё. Этот документ описывает, как это должно работать.

## Принципы

1. **Проверка только на сервере.** Скрытие кнопок в интерфейсе — удобство, а не защита. Каждый server action и каждая страница админки проверяют право сами.
2. **Роль берётся из базы, а не из токена.** Так уже сделано в `requireSession` (`lib/session.ts`): смена роли действует сразу.
3. **Право, а не роль.** Код спрашивает «можно ли `units:write`», а не «это admin?». Роли только сопоставляются наборам прав в одном файле.
4. **Изоляция усадеб остаётся главной.** Права действуют внутри своей усадьбы, фильтр по `propertyId` из сессии никуда не девается.

## Роли

| Роль | Кто это | Идея |
|---|---|---|
| `owner` | Владелец усадьбы | Полный доступ, включая деньги и команду |
| `admin` | Управляющий | Ведёт объекты, цены и заявки, но не трогает деньги и команду |
| `staff` | Администратор на ресепшене | Работает с заявками и календарём, остальное только смотрит |

## Матрица прав

| Право | Что даёт | owner | admin | staff |
|---|---|:-:|:-:|:-:|
| `leads:read` | Смотреть заявки и карточки | да | да | да |
| `leads:write` | Менять статус, писать заметки | да | да | да |
| `calendar:write` | Закрывать и открывать даты вручную | да | да | да |
| `units:read` | Смотреть дома, тарифы, услуги, тексты | да | да | да |
| `units:write` | Создавать и править дома, тарифы, услуги, фото, тексты, праздники | да | да | нет |
| `units:delete` | Удалять дома, тарифы, услуги | да | нет | нет |
| `settings:write` | Задаток, реквизиты, Telegram, показ цен и занятости, iCal-ленты | да | нет | нет |
| `team:manage` | Приглашать, менять роли, удалять пользователей | да | нет | нет |

## Правила, которые нельзя нарушать

- В усадьбе всегда есть хотя бы один `owner`. Последнему владельцу нельзя понизить себя или удалить себя.
- Пользователь не может выдать роль выше своей.
- Нельзя менять или удалять пользователя другой усадьбы (проверка по `propertyId`).
- Смена роли действует сразу, без перевхода.

## Как это будет в коде

Один файл `lib/permissions.ts`:

```ts
export type Permission =
  | 'leads:read' | 'leads:write' | 'calendar:write'
  | 'units:read' | 'units:write' | 'units:delete'
  | 'settings:write' | 'team:manage'

const ROLE_PERMISSIONS: Record<Role, Permission[]> = {
  owner: [/* все */],
  admin: ['leads:read', 'leads:write', 'calendar:write', 'units:read', 'units:write'],
  staff: ['leads:read', 'leads:write', 'calendar:write', 'units:read'],
}

export const can = (role: Role, p: Permission) => ROLE_PERMISSIONS[role].includes(p)

/** В начале server action: сессия + право. Нет права — понятная ошибка, ничего не меняется. */
export async function requirePermission(p: Permission) {
  const session = await requireSession()
  if (!can(session.role, p)) throw new ForbiddenError(p)
  return session
}
```

- Server actions в `app/admin/actions.ts` вместо `requireSession()` вызывают `requirePermission('…')`.
- Страницы без права получают понятное сообщение «Нет доступа», а не пустую страницу.
- Навигация `AdminNav` показывает только доступные разделы.

## Страница «Команда»

- Список пользователей усадьбы: имя, почта, роль, дата создания.
- Приглашение по почте с выбором роли (на первом этапе можно создавать пользователя с временным паролем).
- Смена роли и удаление, с правилами выше.
- Доступна только с правом `team:manage`.

## Тесты (по образцу `tests/int/security.test.ts`)

- `staff` не может создать, изменить или удалить дом, услугу, тариф; не может менять настройки.
- `admin` может править дома, но не может удалить дом и не может менять настройки и команду.
- `owner` не может удалить или понизить себя, если он последний владелец.
- Никто не может выдать роль выше своей.
- Пользователь усадьбы А не может менять пользователей усадьбы Б.
- Смена роли в базе действует на следующий же запрос.
